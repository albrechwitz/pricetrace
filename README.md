# PriceTrace

내가 구매한 상품의 가격이 언제, 얼마나 달라졌는지 확인하는 개인 구매 이력 도구입니다.

## 개발 동기

우리가 구매하는 물품이 얼마나 되는지, 그리고 그 물품의 가격의 오르내림이 실제로 어느 정도로 얼마만의 기간에 일어나는지를 알고 싶다는 생각이 들었습니다.
현재 상용 서비스는 가계부 형태의 서비스는 지원합니다. 그렇지만 결제 대상과 품목을 카드나 현금 결제로는 알 수 없습니다. 금액의 규모와 용처만 알 수 있죠. 이건 플랫폼 중앙화가 아닌 소비자 기준의 중앙화 - web 3.0의 월렛 - 를 통해도 바뀌지 않는 부분이었습니다.
다행히 온라인 플랫폼에서 구매하거나 페이 서비스를 이용하는 경우에는 물품 정보를 수집한 목록을 확인할 수 있었고, 그 대표적인 방법이 메일 수신 서비스였습니다. 여러 판매처에서 물건을 구매하면 주문 내역은 메일로 수신됩니다. 이 메일폼을 해석하는 도구를 만들고 증강하면 구매한 제품을 원장 목록으로 구현할 수 있고, 반복해서 구매하는 것을 구별할 수 있습니다. 구매 목록과 가격 추적의 경로가 있었습니다.

처음에는 이 아이디어를 에이전트 세션에 위임해서 처리하고 결과를 스프레드시트로 확인했습니다. 이제 이 과정을 반복해서 실행하고 결과를 원문과 대조할 수 있는 프로그램으로 옮겨, 구매 기록 자체보다 **같은 상품의 가격 변화**를 살펴보려 합니다.

## 컨셉

기록을 **상품 → 구매 이력**의 두 단계로 정리합니다. 상품명으로 이력을 묶되 옵션·용량·구성은 구분하고, 판매자와 판매 플랫폼 정보는 판단 근거로 남깁니다.

- 최근 가격과 이전 구매 가격의 차이를 금액과 비율로 확인합니다.
- 소비자가가 없으면 확인 가능한 주문·결제 가격을 기준으로 사용합니다. 할인 내역이 명시된 경우에만 할인가와 할인율을 함께 표시합니다.
- 여러 메일이 같은 구매를 설명하면 하나의 구매로 연결합니다. 확정하기 어려운 경우에는 사용자에게 검토를 요청하고 원문을 확인할 수 있게 합니다.
- 가격은 원화를 기준으로 비교하며 외화 원가를 함께 표시합니다. 실제 원화 금액이 없을 때 사용하는 기준 환율은 카드 청구액과 다를 수 있습니다.

## 현재 지원 범위와 한계

**현재 메일 계정 연동은 Gmail만 지원합니다.** Gmail로 받은 여러 판매처의 주문·결제 메일을 다룰 수 있지만, Outlook·네이버 메일·다음 메일 계정을 직접 연결하는 기능은 아직 없습니다. 네이버 메일은 시도했었으나 보안 설정 문제에서 해결되지 않은 병목이 있었습니다.

메일의 텍스트, HTML 표와 구조화된 주문 정보를 규칙으로 해석합니다. 현재는 쿠팡, 컬리등 주요 플랫폼의 메일폼만 해석합니다. 아직 이미지는 에이전트 세션에만 묶여있고 분석하는 도구를 만들지 않았습니다. 상품명에 기반한 묶음도 실제로 같은 제품임을 완전히 보장하지는 않습니다. 그래서 검토 과정을 두었습니다.

구매 기록은 사용 중인 브라우저에 보관됩니다. 서버에서 여러 기기로 동기화하는 기능은 없으며, 다른 환경으로 기록을 옮길 때는 백업과 복원을 사용합니다. 메일 원문은 사이트 서버나 외부 AI에 전송하지 않습니다.

## 구현 방향

현재 구현은 HTML, CSS, JavaScript ES Modules를 사용합니다. 브라우저에서 직접 실행하는 작은 도구의 범위에 맞춰 프레임워크와 별도 빌드 과정 없이 시작했고, 메일 해석·상품 식별·가격 계산·저장 로직은 모듈로 분리했습니다. 초기에는 수집한 기록을 해석하고 검증하는 문제에 집중하며, 이후 화면과 상태 관리의 복잡도가 커지면 그 필요에 맞춰 구조와 도구를 검토합니다.
